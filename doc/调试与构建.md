# ODMatrix 调试与构建

## 1. 目标

本文档说明 `ODMatrix` 在本地环境中的引用、构建、部署与验证方式。

## 2. 环境要求

- Windows 开发环境
- Visual Studio
- .NET Framework 3.5 Targeting Pack
- Cities: Skylines 1 本体
- 与项目中引用版本兼容的游戏 DLL

## 3. 本地引用说明

当前项目文件直接引用了本地游戏安装目录中的 DLL：

- `Assembly-CSharp.dll`
- `ColossalManaged.dll`
- `ICities.dll`
- `UnityEngine.dll`

这类引用具有明显的机器相关性。为避免多人协作时反复修改并提交 `ODMatrix.csproj`，项目改为仅通过 `ODMatrix.csproj.user` 中的属性 `CitiesSkylinesManagedDir` 管理路径。

推荐在本地创建 `ODMatrix.csproj.user`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Project>
    <PropertyGroup>
        <CitiesSkylinesManagedDir>D:\SteamLibrary\steamapps\common\Cities_Skylines\Cities_Data\Managed</CitiesSkylinesManagedDir>
    </PropertyGroup>
</Project>
```

该文件已加入 `.gitignore`，不会参与版本控制。

## 4. NuGet 依赖

当前 `packages.config` 中的依赖为：

- `CitiesHarmony.API` 2.2.0
- `CitiesHarmony.Harmony` 2.2.2

若依赖未自动还原，需先完成 NuGet 还原后再构建。

## 5. 构建步骤

### 5.1 打开解决方案

打开：

- `ODMatrix.slnx`

### 5.2 检查引用

确认以下内容无黄色警告：

- 游戏 DLL 本地引用
- NuGet 包引用
- 目标框架为 `.NET Framework 3.5`

### 5.3 执行构建

可使用 Visual Studio 直接构建 `Debug` 或 `Release`。

输出目录默认为：

- `bin\Debug\`
- `bin\Release\`

## 6. Mod 部署建议

项目最终产物是 DLL，需要复制到 Cities: Skylines 的 Mod 目录中。

建议调试部署目录：

`%LOCALAPPDATA%\Colossal Order\Cities_Skylines\Addons\Mods\ODMatrix\`

建议将以下文件放入同一目录：

- `ODMatrix.dll`
- 运行时需要的依赖 DLL（如实现期有额外要求）

如果后续引入配置文件、说明文件或图标资源，也应一并复制。

## 7. 基础验证流程

## 7.1 启动验证

- 启动游戏
- 在内容管理器中确认 Mod 可见
- 进入地图或存档
- 查看是否有初始化日志

## 7.2 功能验证

在最小补丁阶段，建议只验证以下内容：

- 补丁是否成功应用
- 候选方法是否被触发
- 日志是否能输出捕获计数

在调试模式阶段，额外验证：

- 是否能够保留原始居民出行记录
- 是否能够保留游客出行记录
- 是否可人工抽样核对 Origin / Destination 与 Purpose
- 原始记录与聚合结果是否一致
- 是否能正确区分 `PrimaryIntent` 与 `Retry`

在导出阶段，再验证：

- JSON 文件是否生成
- 文件命名是否符合预期
- 内容结构是否符合 `doc/数据模型.md`

在正式模式阶段，再验证：

- 网格顺序索引是否稳定
- 压缩整数记录是否可正确还原为导出矩阵
- 路径层对照埋点数量是否持续增长
- 意图层数量与 `PathManager.CreatePath` 对照数量是否存在可解释关系

### 7.2.1 0.1.3 已验证结论

基于 `odmatrix_20260527_101429.log`，当前版本已验证：

- 反射探针与 Harmony 补丁均成功加载和卸载
- 会话内共记录 `8440` 次 transfer，其中 `PrimaryIntent=8430`、`Retry=10`
- 居民事件 `7899`，游客事件 `541`
- `PathManager.CreatePath` 对照请求累计 `26603`
- `Retry` 主要集中在 `Work` 与少量 `Social`
- `sameOriginAndDestination=0`，说明本次样本中未出现同楼起终点型误判

当前可据此采用的分析口径：

- 后续 OD 聚合主口径使用 `PrimaryIntent`
- `Retry` 保留用于诊断、阈值复核与异常样本审查
- `PathManager.CreatePath` 继续作为路径层对照，不直接并入主 OD 计数

### 7.2.2 游戏内时间验证方向

当前新增设计决策要求在数据中体现游戏内时间。基于对依赖 DLL 的反射检查，已确认以下成员存在：

- `SimulationManager.m_currentGameTime`
- `SimulationManager.m_currentDayTimeHour`
- `SimulationManager.m_dayTimeFrame`
- `SimulationManager.FrameToTime(uint frame)`
- `DayNightProperties.normalizedTimeOfDay`

后续实现与验证时，建议至少检查：

- 记录的 `GameTime` 是否随游戏推进连续变化
- 暂停、加速、昼夜切换时 `GameTime` 与 `NormalizedTimeOfDay` 是否同步合理
- 同一条事件的 `CapturedAtUtc` 与 `GameTime` 是否可同时用于日志对账与游戏内分时分析

## 7.3 故障排查

### 常见问题 1：构建失败，找不到游戏程序集

检查：

- `CitiesSkylinesManagedDir` 是否指向你的实际安装路径
- 游戏是否已安装且文件完整

### 常见问题 2：游戏中看不到 Mod

检查：

- 输出 DLL 是否复制到正确目录
- 文件夹层级是否正确
- 是否缺失依赖 DLL

### 常见问题 3：Mod 加载但无任何日志

检查：

- 入口类是否被正确实现
- Harmony 初始化是否执行
- 日志调用是否放在实际触发路径上

### 常见问题 4：JSON 导出失败

检查：

- 输出目录是否存在写权限
- 序列化库是否兼容 net35
- 快照对象中是否包含不可序列化字段

## 8. 调试建议

- 初期优先使用最少日志验证关键链路
- 不要在高频补丁中输出大量日志
- 对异常统一捕获并输出简短上下文
- 每增加一个模块，就补一次最小验证

日志策略要求：

- 游戏日志只写启动、关闭、补丁初始化、导出摘要
- 详细调试日志写入本 Mod 独立日志文件
- 调试模式下的人工稽核信息不得污染游戏总日志
- 统计摘要应区分总触发数、主意图数、重试数、游客数和对照埋点数
- 如已接入游戏内时间字段，摘要或抽样日志应能同时显示现实时间与游戏内时间

建议的独立日志目录：

- `%LOCALAPPDATA%\Colossal Order\Cities_Skylines\ODMatrix\Logs\`

## 9. 发布前检查清单

- `Release` 构建通过
- 无本地调试残留开关
- 输出目录与文件命名稳定
- JSON 结构与文档一致
- 游戏内时间字段口径与文档一致
- 基本场景下无明显报错或卡顿
- 调试模式与正式模式的日志行为符合预期
