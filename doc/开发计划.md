# ODMatrix 开发计划

## 1. 文档目的

本文档用于把当前需求文档转化为可执行的采集端开发计划，聚焦 MVP 范围、里程碑与交付标准。

## 2. 当前项目状态

当前已完成：

- 解决方案创建
- 基础依赖接入
- 游戏程序集本地引用接入
- 文档体系建立

当前未完成：

- 运行时功能代码
- 最小可用补丁
- 数据导出链路
- 调试与验证工具

## 3. MVP 范围

MVP 仅关注“采集端跑通”，包含以下能力：

- Mod 可被游戏正确加载
- Harmony 补丁能在候选埋点触发
- 能采集 Origin / Destination 基础信息
- 能在调试模式下保留原始记录用于人工稽核
- 能覆盖居民与游客两类意图事件
- 能区分 `PrimaryIntent` 与 `Retry`
- 能将坐标转为网格 ID
- 能将网格映射为稳定整数索引
- 能按至少一种出行目的完成聚合
- 能记录路径层对照埋点统计
- 能手动导出 JSON 文件
- 能通过独立日志验证快照已生成

MVP 不包含：

- 完整的游戏内 UI 面板
- 所有出行目的的精细识别
- 自动存档联动
- 高级性能统计图
- Web 可视化端开发

## 4. 里程碑拆分

## M0：项目基线

目标：建立可持续开发基础。

任务：

- 确认项目可编译
- 确认本地 DLL 路径可维护
- 明确文档、数据结构与目录规范
- 明确后续代码组织到 `src/` 目录

完成标准：

- 仓库文档完整
- 开发者可据此进入编码阶段

## M1：入口与补丁链路

目标：让 Mod 在游戏中启动，并验证补丁点可触发。

任务：

- 添加 `IUserMod` 与加载入口
- 初始化与卸载 Harmony
- 选定候选埋点并输出调试日志

完成标准：

- 游戏启动后可看到 Mod 加载信息
- 候选埋点在目标场景下触发

## M2：事件采集与缓冲

目标：建立稳定的原始事件采集管道。

任务：

- 定义 `ODEvent`
- 定义压缩记录模型
- 实现去重键与时间窗口分类
- 实现 `Queue<T> + lock` 缓冲区
- 完成事件入队与批量消费

完成标准：

- 主线程无明显卡顿
- 独立日志可看到事件计数增长
- 调试模式下可抽样核对原始记录
- 能区分主意图与重试事件

## M3：聚合与导出

目标：输出首个可用 JSON 快照。

任务：

- 实现网格映射
- 实现固定网格顺序索引
- 实现 outbound / inbound 双向聚合
- 实现游客纳入与主意图优先聚合
- 实现对照埋点统计汇总
- 实现手动导出触发
- 实现文件写入与异常处理

完成标准：

- 成功写出 JSON
- JSON 可被后续前端按约定解析

## M4：稳定性增强

目标：提高容错性与可维护性。

任务：

- 增加配置项
- 增加导出节流与周期策略
- 增加异常保护与诊断日志
- 校验长时间运行内存表现

完成标准：

- 连续运行下无明显异常积累
- 日志可帮助定位常见问题

## 6. 验收标准

当以下条件全部满足时，可认为采集端 MVP 完成：

- 游戏能加载 Mod 且不报错
- 至少一个真实运行场景中能持续捕获事件
- 导出 JSON 符合既定结构
- 不在高频逻辑中进行磁盘写入
- 调试模式可对原始记录进行人工稽核
- 游客事件被纳入统计
- 主意图与重试可被区分
- 对照埋点可输出可解释统计
- 代码与文档一致

## 7. 推荐开发顺序

1. 先打通加载与生命周期摘要日志
2. 再验证补丁点
3. 再做最小原始事件对象
4. 再补抓游客意图
5. 再做去重与主意图分类
6. 再加对照埋点
7. 再做调试模式原始记录保留
8. 再做网格映射与整数索引
9. 再做聚合器
10. 最后做导出、独立日志与配置

## 8. 风险跟踪

当前已知风险：

- 候选补丁点未必能可靠表达“真实出行意图”
- net35 限制了并发容器与现代语法的使用
- 游戏升级、其他 Mod 补丁冲突可能影响稳定性
- 序列化方案需单独验证兼容性

## 9. 下一步建议

建议下一次开发直接从 `M1：入口与补丁链路` 开始，并先交付一个“只打日志、不做聚合”的最小补丁版本，用于验证技术路线。

## 10. 当前版本关注点（0.1.2）

0.1.2 的核心目标不是新增更多采集入口，而是加强对现有意图层数据的正确性诊断。

本版本重点观察：

- 按 `Purpose` 的主意图/重试分布是否合理
- 游客与居民在不同 `Purpose` 下的比例是否可解释
- `Retry` 是否主要集中在工作、上学等更容易重复触发的类别
- 同一 citizen 的重复样本是否能通过时间差和上一主意图上下文解释

0.1.3 将基于这些日志结果进一步收敛最终的统计口径。
